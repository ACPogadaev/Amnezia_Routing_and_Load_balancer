# Amnezia Router — универсальная версия 0.1.0

Выборочная маршрутизация IPv4 для **уже установленного входного AmneziaWG-сервера**.
Одна установка принимает от одного до трёх клиентских AWG-профилей внешних серверов
и два независимых списка адресов.

| Вход | Поведение |
|---|---|
| 1 AWG-профиль | Целевой трафик идёт через единственный выход |
| 2 AWG-профиля | Балансировка между двумя здоровыми выходами |
| 3 AWG-профиля | Балансировка между тремя здоровыми выходами |
| `--balanced-routes` | Первый файл: IPv4/CIDR, распределяемые по доступным выходам |
| `--pinned-routes` + `--pin-egress N` | Второй файл: IPv4/CIDR только через выбранный выход |
| Назначение в обоих списках | Приоритет закреплённого списка |
| Закреплённый выход не работает | Его адреса блокируются до восстановления |
| Назначение отсутствует в списках | Сохраняется прямой путь через балансировщик |

Это первая реализация нового самостоятельного runtime. Выполнена полная установка
на Ubuntu 24.04 с Docker 29 и тремя реальными AWG-профилями. Через временный
зашифрованный VPN-клиент проверены балансировка, закрепление, прямой путь,
отказ/возврат закреплённого выхода и восстановление после перезапуска Docker.
Варианты с 1–3 выходами дополнительно проверяются в изолированных Linux namespace.
Старые `templates/v2`, `templates/v3` и их инструкции сохранены отдельно для сравнения
и существующих установок. Перезагрузка всей ОС и другие дистрибутивы отдельно не проверялись.

## Установка одной командой

После распаковки пакета в каталог `amnezia-router`:

```bash
sudo bash install.sh --egress /root/exit1.conf --egress /root/exit2.conf --egress /root/exit3.conf --balanced-routes /root/balanced.txt --pinned-routes /root/pinned.txt --pin-egress 2
```

В рабочей копии Git эта же команда запускается из корня репозитория.
Для двух выходов передайте два `--egress`, для одного — один. Номера выходов
соответствуют порядку аргументов. Второй список необязателен:

```bash
sudo bash install.sh --egress /root/exit1.conf --balanced-routes /root/balanced.txt
```

В Git-репозитории есть открытые нормализованные снимки списков от 3 ноября 2026:
`routes/balanced-ipv4-2026-11-03.cidr.txt` и
`routes/ai-pinned-ipv4-2026-11-03.cidr.txt`. Это примеры адресной политики;
профили выходов передаются отдельно и не публикуются. Снимки не входят в автономный
пакет установщика: при установке из архива передайте свои файлы либо скачайте
нужный снимок из репозитория отдельно.

Маршрут выбирается по IP назначения. Скачивание файла, запущенное AI-агентом,
идёт по адресу сайта с файлом; оно не наследует закрепление API-сервиса.
Широкие сети во втором списке закрепляют также другие сервисы с адресами в этих сетях.

Имя входного контейнера по умолчанию — `amnezia-awg2`. Для другого имени добавьте:

```bash
--ingress-container my-existing-amnezia
```

Установщик извлекает из контейнера интерфейс AWG, клиентскую подсеть, UDP-порт,
Docker-сети и используемый локальный образ. Для нескольких AWG-интерфейсов укажите
`--ingress-interface awg0`. Если адрес ingress-интерфейса задан с `/32`, явно
передайте реальную клиентскую подсеть: `--client-subnet 10.8.1.0/24`.

Ожидаемый публичный IP каждого выхода по умолчанию равен IP из `Endpoint`.
Если внешний сервер использует другой публичный IP для NAT, добавьте, например:

```bash
--expected-exit 2=203.0.113.20
```

В примере используется адрес документации; в рабочем запуске нужен реальный IP.

Установка не скачивает и не исполняет скрипты из AWG-профилей. `PreUp`, `PostUp`,
`PreDown`, `PostDown`, `DNS` и параметры автоматической маршрутизации удаляются
из локальной подготовленной копии. Приватные ключи сохраняются только в
`/etc/amnezia-router/secrets/` с правами `0600`, каталог — `0700`.

## Проверки до изменения системы

Добавьте `--check-only` к команде установки:

```bash
sudo bash install.sh --egress /root/exit1.conf --egress /root/exit2.conf --balanced-routes /root/balanced.txt --pinned-routes /root/pinned.txt --pin-egress 2 --check-only
```

Этот режим читает окружение и формирует план, не меняя файлы установки, службы,
Docker-сети, firewall или маршруты.

Проверяются:

- Linux, root, Python 3.10+, работающий systemd, `/dev/net/tun`;
- Ubuntu 22.04/24.04 либо Debian 12/13 как заявленная целевая платформа;
- локальный Docker Engine с `network connect --gw-priority` (28+), Compose v2+, `iptables-nft`, nftables, iproute2,
  util-linux, Bash, curl и инструменты AWG в установленном образе;
- существующий ingress в bridge-сетях, его подсеть и единственный исходный default;
- единственный default route хоста и включённый IPv4 forwarding;
- от 1 до 3 корректных AWG-профилей с одним peer, числовым IPv4 endpoint,
  допустимым UDP-портом и `AllowedIPs = 0.0.0.0/0`;
- существование выбранного номера выхода для закреплённого списка;
- свободные Docker-имена, bridge-имена, policy tables и priorities;
- отсутствие конфликтов выбранных внутренних подсетей с маршрутами и Docker IPAM;
- отсутствие активной старой установки Amnezia LB v2/v3.

При недостающих зависимостях программа завершает работу с описанием проблемы.
Она не переустанавливает Docker и не меняет сетевой backend автоматически.
Для системных утилит обычно требуется:

```bash
sudo apt-get install python3 iproute2 iptables nftables util-linux bash curl
```

Docker Engine и Compose plugin должны быть уже установлены. Новые egress-контейнеры
используют точный ID локального образа ingress; загрузка образа из сети не нужна.
Если в этом образе нет нужных утилит, можно заранее подготовить отдельный
локальный образ и передать `--egress-image IMAGE`; ingress при этом не меняется.
Окружение `DOCKER_HOST`/`COMPOSE_*` не может переключить установку на другой Docker
daemon или изменить имя проекта.

Существующие нестандартные policy rules приводят к отказу автоматической установки:
их взаимодействие с новой маршрутизацией требует отдельной настройки. Установка
поверх действующего v2/v3 также требует отдельной миграции; эта версия не выполняет
её на работающем сервере.

## Формат файлов

`balanced.txt`:

```text
# Один IPv4 или CIDR на строку
93.184.216.0/24
8.8.8.8/32
```

`pinned.txt`:

```text
# Этот адрес будет направляться только через --pin-egress
93.184.216.34/32
```

Комментарии после `#` и пустые строки разрешены. Дубликаты и вложенные сети
объединяются, адреса с host bits канонизируются. IPv6 и доменные имена отклоняются.
Служебные, локальные и multicast диапазоны удаляются по вложенной классификации
IANA. В пакет включён официальный CSV, полученный 3 ноября 2026:
[IANA IPv4 Special-Purpose Address Registry](https://www.iana.org/assignments/iana-ipv4-special-registry/iana-ipv4-special-registry.xhtml).
Во время установки доступ к IANA не нужен. Если непустой список после фильтрации
полностью исчезает, установка завершается ошибкой. Пустой первый файл допустим,
когда задан непустой второй список.

## Эксплуатация и удаление

```bash
sudo amnezia-router status
sudo amnezia-router doctor
sudo journalctl -u amnezia-router -f
```

`status` возвращает `0`, когда все выходы здоровы, `1` при деградации с доступным
выходом и `2` при блокировке, устаревшем состоянии или недоступности закреплённого
выхода при наличии второго списка. `doctor` читает текущие правила без исправлений.

Программа создаёт отдельный Compose-проект `amnezia-router` и только необходимые
сервисы `egress1`…`egress3`. При выключении/удалении применяется явное имя проекта,
без `--remove-orphans`. Контейнер ingress не удаляется и не пересоздаётся.

Остановка службы блокирует целевые маршруты; обычный прямой путь остаётся
настроенным. При ошибке установки защита сохраняется. Возврат всех адресов к
исходной прямой маршрутизации выполняется явной командой:

```bash
sudo amnezia-router uninstall --restore-direct
```

Удаляются только сетевые ресурсы и службы программы. Исходный default route
ingress не заменяется ни при установке, ни при удалении. Исходные sysctl сохранены
до изменения и восстанавливаются при удалении. Профили и установленный код
архивируются в соседние каталоги с суффиксом `.uninstalled-...`, baseline сохраняется
в `/var/lib/amnezia-router`. После удаления можно снова установить программу
с другим количеством выходов, порядком профилей или списками.

## Поведение при отказах

После трёх неуспешных свежих проверок выход исключается из новых назначений и
одновременно попадает в двусторонний quarantine существующих потоков. Ошибка
выходного IP или ключевого локального правила закрывает выход сразу.
После трёх успешных проверок выход возвращается. Повтор одного cached sample
не увеличивает счётчики. Интервал по умолчанию — 10 секунд (`--interval`).

Балансировка использует стабильные destination buckets и EWMA текущего трафика.
Уже созданное соединение закрепляется через conntrack и не переносится на другой
публичный IP. Популярный адрес может нагружать один выход сильнее остальных.
Закреплённый список всегда проверяется до балансировки, включая отказ его выхода.
При отказе всех выходов оба списка блокируются.

Защита nftables загружается до запуска Docker через systemd dependency. Проверки
правил, namespace identity, точных policy lookup/unreachable и sysctl выполняются
повторно в работающем контроллере. При расхождении целевой допуск закрывается.
Отдельный admission fence позволяет закрыть целевой lookup до ремонта правил.

Docker может перезапустить упавший процесс контейнера через `unless-stopped`.
Автоматические `docker restart` при сетевых отказах в этой версии не выполняются.

## Автономный план и тесты

Для проверки файлов без Linux/Docker нужен JSON описания окружения. Пример
синтетического описания находится в `examples/ingress.json`:

```bash
python3 routerctl.py plan --egress /path/exit1.conf --balanced-routes examples/balanced.txt --pinned-routes examples/pinned.txt --pin-egress 1 --ingress-info examples/ingress.json --output /tmp/amnezia-plan
```

В плане есть конфигурация без ключей, Compose и nftables batch-файлы. Файлы плана
не устанавливаются автоматически. План использует синтетическое окружение из JSON;
проверка действительного сервера выполняется через `install --check-only`.

Из корня Git-репозитория:

```bash
python3 -m unittest discover -s universal/tests -v
find universal -name '*.sh' -print0 | xargs -0 -n 1 bash -n
sudo env AMNEZIA_ROUTER_INTEGRATION=1 python3 -m unittest discover -s universal/tests -p test_kernel.py -v
python3 universal/tools/package.py /tmp/amnezia-router-0.1.0.tar.gz
```

Kernel-тест создаёт отдельные namespace/veth, передаёт реальные UDP-пакеты через
сгенерированный nft selector для 1–3 выходов, проверяет закрепление, quarantine
существующего потока и `unreachable` после потери маршрута. Он не запускает Docker,
настоящий AWG или установщик. Полная приёмка требует отдельного Linux-стенда с
реальными профилями: установка, прямой/балансируемый/закреплённый трафик, отказ
каждого выхода, перезапуск Docker, перезагрузка и удаление.

Для пакета создаются общий SHA256 и внутренний `SHA256SUMS`. Перед установкой
из распакованного каталога можно выполнить `sha256sum -c SHA256SUMS`.
