# Amnezia VPN route balancer

Маршрутизатор для существующего входного AmneziaWG-сервера: только IPv4-трафик к заданному списку CIDR уходит через один из трёх внешних AmneziaWG-туннелей, остальной клиентский трафик продолжает выходить напрямую через сервер-балансировщик.

Проект рассчитан на Ubuntu 24.04 LTS, Docker Engine, systemd, nftables и iproute2. Он не устанавливает Amnezia вместо официального клиента и не содержит ключей, паролей, реальных endpoint-адресов или пользовательского списка маршрутизации.

> **Важно:** это сетевой проект с fail-closed правилами. Ошибка в параметрах может временно лишить VPN-клиентов доступа к целевым адресам. Первый запуск выполняйте при наличии отдельной SSH-сессии и VNC/консоли провайдера.

## Что реализовано

- один существующий входной контейнер AmneziaWG;
- три изолированных исходящих AmneziaWG-клиента;
- классификация только адресов из пользовательского IPv4 CIDR-списка;
- 256 стабильных buckets по адресу назначения;
- привязка уже созданного соединения через `ct mark`;
- вывод из балансировки после серии неуспешных health-check;
- возврат после серии успешных проверок;
- учёт недавней скорости туннеля при распределении новых соединений;
- `unreachable` после каждого policy lookup и общий fail-closed путь;
- атомарная загрузка nftables-наборов;
- необязательное диагностическое логирование маршрутов с rate limit;
- проверки конфигурации, контрольные суммы, preflight, verify и откат.

## Что намеренно отсутствует в Git

- SSH-пароли и ключи серверов;
- `PrivateKey`, `PresharedKey` и полные AWG-конфигурации;
- реальные IP и UDP-порты VPN-серверов;
- пользовательский `routes.txt`;
- сгенерированный каталог `dist/`.

`.gitignore` исключает эти данные, а сборщик принимает их только локально.

## Минимальная последовательность

На рабочей машине или на сервере:

```bash
git clone https://github.com/ACPogadaev/amnezia-vpn-route-balancer.git
cd amnezia-vpn-route-balancer
cp config/deployment.env.example config/deployment.env
nano config/deployment.env
python3 tools/fetch-iana-registry.py
python3 tools/build-release.py \
  --config config/deployment.env \
  --routes /secure/path/routes.txt \
  --iana-csv data/iana-ipv4-special-registry.csv \
  --output dist/release
```

Сборщик:

1. проверяет обязательные параметры;
2. канонизирует и объединяет CIDR;
3. удаляет служебные диапазоны по наиболее специфичному назначению IANA;
4. отдельно исключает multicast `224.0.0.0/4`;
5. создаёт атомарные nftables batch-файлы;
6. пересчитывает контрольные суммы;
7. отказывается продолжать при плейсхолдерах или пустом результате.

Дальнейшая установка выполняется по [пошаговой инструкции](docs/INSTALL.md).

## Ограничения

- только IPv4;
- ровно три egress-туннеля в текущей версии;
- балансируется число новых соединений/buckets, а не каждый пакет;
- один популярный IP закрепляется за одним выходом, поэтому идеальное выравнивание полосы не гарантируется;
- существующие TCP-соединения не мигрируют между выходами;
- обнаружение отказа не мгновенное: при значениях по умолчанию около 20–30 секунд плюс timeout проверок;
- проект предполагает уже установленный AmneziaWG ingress-контейнер и локальный Docker-образ `amnezia-awg2`.
